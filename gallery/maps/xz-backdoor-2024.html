xz Utils backdoor (CVE-2024-3094)

In March 2024 a developer found a hidden backdoor in xz Utils 5.6.0 and 5.6.1, a compression library used by many Linux systems. An account named Jia Tan had spent years earning trust and release rights in the project. The malicious code sat in disguised test files and in a build file found only in the release archives, and it targeted the OpenSSH server on some Linux distributions. It was caught while it was mostly in testing and rolling releases.

Attack flow

  1. 1 Account builds trust with the maintainer over years

    Resource Development

    Jia Tan account → Original xz Utils maintainer

    From late 2021 an account named Jia Tan sent small, useful patches to the xz project and began working with its long-time maintainer away from the public list. CISA later described this as a threat actor spending several years earning the maintainer's trust in order to plant a backdoor. By mid 2022 the maintainer said Jia Tan might take a bigger role in the project.

    Sources: [11] [8] [9]

  2. 2 Other accounts pressure the maintainer to hand over control

    Resource Development Reported

    Pressure accounts on the xz mailing list → Original xz Utils maintainer

    In 2022 accounts such as Jigar Kumar complained on the xz mailing list about slow progress and pushed for a new maintainer. The maintainer replied that he had limited time for the unpaid project. A public timeline says these addresses left almost no trace elsewhere online and were likely fake identities made to push for giving Jia Tan more control. Open source foundations later listed this pattern as a warning sign.

    Sources: [8] [9] [12]

  3. 3 Jia Tan gains commit and release rights

    Privilege Escalation

    Jia Tan account → xz Utils repository and releases

    Over 2022 and 2023 Jia Tan became a co-maintainer with commit access and control of the project's GitHub-hosted assets. The original maintainer later confirmed that the 5.6.0 and 5.6.1 release archives were made and signed by Jia Tan, while the main website and its git copies stayed under his own control.

    Sources: [7] [9]

  4. 4 A fuzzing build setting is turned off

    Defense Impairment Reported

    Jia Tan account → xz Utils repository and releases

    In July 2023 Jia Tan turned off support for a CPU feature-selection mechanism called ifunc in the project's OSS-Fuzz builds. A public timeline says the change may have been harmless on its own but also looks like groundwork, and the backdoor later abused that same mechanism. No primary source confirms the intent of this change.

    Sources: [9] [6]

  5. 5 Hidden payload committed as binary test files

    Stealth T1027

    Jia Tan account → xz Utils repository and releases

    Before the 5.6.0 release, two binary files presented as compressed test data were added to the repository. No real test used them. Instead they held obfuscated parts of the backdoor, including a prebuilt object file, which looked like ordinary test data to anyone reading the source.

    Sources: [6] [3] [2]

  6. 6 Release archives ship a tampered build file

    Initial Access T1195.002

    Jia Tan account → xz Utils repository and releases

    The 5.6.0 and 5.6.1 release archives from early 2024 included a modified build macro file that was not in the git repository. During the build it quietly started an obfuscated script that pulled the hidden code out of the test files. Because the trigger existed only in the downloadable archives, reading the git source did not reveal it.

    Sources: [6] [7] [3] [1]

  7. 7 Backdoored versions reach Linux distributions

    Initial Access

    xz Utils repository and releases → Linux distributions (testing and rolling builds)

    Debian testing, unstable and experimental packaged the affected versions, as did Fedora Rawhide, Fedora 41 development builds and the Fedora 40 beta. Red Hat said no Red Hat Enterprise Linux version was affected, and Debian said no stable release was known to be affected, so most production systems never received it.

    Sources: [5] [4] [3]

  8. 8 Package build injects code into liblzma

    Execution

    xz Utils repository and releases → Linux distributions (testing and rolling builds)

    When the library was built as a Debian or RPM package for x86-64 Linux with GCC and the GNU linker, the hidden script extracted the prebuilt object and linked it into liblzma. The resulting library changed some of its own functions, so any program that loaded it could have its data intercepted or altered.

    Sources: [6] [2] [3]

  9. 9 Backdoor checks its surroundings to stay hidden

    Stealth Reported

    Jia Tan account → OpenSSH servers that load liblzma

    At run time the code only acted when things looked like a normal sshd start, for example by checking environment settings, and it appeared to notice some debuggers. The finder believed the package-build condition was meant to make the issue harder for investigators to reproduce. Version 5.6.1 also adjusted the code after it caused crashes and memory-checker errors.

    Sources: [6]

  10. 10 Backdoor hooks OpenSSH login checks

    Credential Access T1556

    Linux distributions (testing and rolling builds) → OpenSSH servers that load liblzma

    Several distributions patch OpenSSH to notify systemd, which makes sshd load libsystemd and, through it, liblzma, even though OpenSSH does not use liblzma itself. As sshd started, the backdoor redirected an RSA check that sshd uses during public key login to its own code, so it could inspect login attempts before authentication finished.

    Sources: [6] [3]

  11. 11 Attacker could gain access to affected SSH servers

    Execution Reported

    Jia Tan account → OpenSSH servers that load liblzma

    CISA and Red Hat said the hook could let a remote attacker get around SSH login checks and gain access to the whole system. Later analysis cited in a community FAQ said it acted only on input signed with the attacker's private key, checked against a public key built into the backdoor. The finder had not fully analyzed it at disclosure, and none of the cited sources reports a confirmed compromise that used it.

    Sources: [1] [4] [6] [10]

Impact

The backdoor reached only development, testing and rolling Linux releases such as Debian testing and unstable, Fedora Rawhide and the Fedora 40 beta. No Debian stable or Red Hat Enterprise Linux version was affected. On systems that did run it, the CVE record rates the flaw critical (CVSS 10.0). CISA said it was spotted before it caused significant harm, but it showed how fragile and overloaded key open source projects can be.

Sources: [5] [4] [2] [11]
