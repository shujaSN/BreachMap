Log4Shell: remote code execution in Apache Log4j 2 (CVE-2021-44228)

Log4Shell is a critical flaw in Apache Log4j 2, a Java logging library built into thousands of products. Versions 2.0-beta9 to 2.14.1 resolved JNDI lookups found inside logged text, so an unauthenticated attacker who got crafted text logged could make the server fetch and run code from a server the attacker controlled. After details went public in December 2021, mass scanning followed, then coin miners, botnets, ransomware and suspected state-backed intrusions.

Attack flow

  1. 1 Scan the internet for vulnerable services

    Reconnaissance T1595.002

    Attackers (criminal and suspected state-backed) → Internet-facing Java application or appliance

    Soon after the flaw became public, attackers and researchers swept the internet for systems running vulnerable Log4j. The FBI saw widespread scanning aimed at gaining network access. The CSRB notes vendors logged millions of probes, some automated through botnets, which made malicious traffic hard to tell apart from research scans.

    Sources: [4] [6]

  2. 2 Get crafted lookup text written to the log

    Initial Access T1190

    Attackers (criminal and suspected state-backed) → Internet-facing Java application or appliance

    The attacker places a specially formed lookup expression into any input the target is likely to log, such as a web request header, a form field or a chat message. No account and no user action are needed. Attackers soon disguised this text with encoding tricks to slip past simple filters.

    Sources: [1] [2] [7] [8]

  3. 3 Log4j resolves the lookup and calls the attacker's server

    Execution

    Apache Log4j 2 (log4j-core) → Attacker-controlled LDAP/JNDI server

    When the app passes that text to Log4j, vulnerable versions treat the expression as a JNDI lookup and resolve it. The server then opens an outbound connection, for example over LDAP, to an address the attacker picked. This lookup feature was added in 2013. The callback alone also tells the attacker which hosts are vulnerable, and many campaigns used it to fingerprint targets first.

    Sources: [1] [2] [6] [7]

  4. 4 The attacker's server returns code that the app runs

    Execution

    Attacker-controlled LDAP/JNDI server → Internet-facing Java application or appliance

    The attacker's server answers the lookup with code of its choosing. The vulnerable process loads and runs it with the application's own rights, which gives the attacker full control of that system. Apache rated this 10.0, the highest score, because it is easy to pull off and needs no privileges or user interaction.

    Sources: [1] [2] [4] [6]

  5. 5 Leak secrets through the lookup itself

    Exfiltration Reported

    Apache Log4j 2 (log4j-core) → Attacker-controlled LDAP/JNDI server

    Some attackers did not need to run code at all. They used Log4j's other lookup features to fold data such as environment variables, system details or credentials into the outbound request, so the secrets reached the attacker's server as part of the callback. Microsoft also saw data leakage through the flaw without any payload being dropped.

    Sources: [8] [7]

  6. 6 Install coin miners and botnet malware

    Impact T1496

    Attackers (criminal and suspected state-backed) → Internet-facing Java application or appliance

    Much of the early follow-on activity aimed at quick profit. The FBI saw attackers deploy cryptocurrency miners and botnet malware on vulnerable systems. Microsoft reported the flaw being quickly added to existing botnets such as Mirai, and the CSRB cites Cisco Talos seeing the same.

    Sources: [4] [7] [6]

  7. 7 Plant web shells and remote access tools

    Command and Control

    Attackers (criminal and suspected state-backed) → Internet-facing Java application or appliance

    In more targeted intrusions, attackers used the foothold to install tools for lasting control. CISA and the U.S. Coast Guard Cyber Command found loader malware with remote control features and a web shell on hacked VMware Horizon servers. Microsoft also saw Cobalt Strike, reverse shells and other remote access tools.

    Sources: [5] [7]

  8. 8 Move deeper into the network over RDP

    Lateral Movement T1021.001

    Internet-facing Java application or appliance → Victim's internal network

    In one case CISA described, the attackers used administrator credentials, obtained in a way investigators could not determine, and Remote Desktop Protocol to reach other hosts, including a security management server, a certificate server and a database with sensitive law enforcement data. Microsoft separately saw Cobalt Strike used for credential theft and lateral movement.

    Sources: [5] [7]

  9. 9 Collect and send out sensitive data

    Exfiltration Reported

    Victim's internal network → Attackers (criminal and suspected state-backed)

    In the same VMware Horizon case, the attackers gathered data from the production environment, and CISA says they likely exfiltrated it. A security management server sent more than 130 GB of data during that period, and archives of law enforcement investigation data were found.

    Sources: [5]

  10. 10 Sell access or deploy ransomware

    Impact T1486 Reported

    Attackers (criminal and suspected state-backed) → Victim's internal network

    Microsoft reported access brokers using the flaw to break into networks and then selling that access to ransomware affiliates, and ransomware such as Khonsari and NightSky delivered through it. The CSRB notes a security firm investigated several ransomware incidents that used Log4j between January and March 2022.

    Sources: [7] [6]

  11. 11 State-linked groups exploit unpatched servers

    Initial Access T1190 Reported

    Attackers (criminal and suspected state-backed) → Internet-facing Java application or appliance

    Microsoft said several nation-state groups it tracks, from China, Iran, North Korea and Turkey, used the flaw, naming PHOSPHORUS (Iran) and HAFNIUM (China). CISA and the Coast Guard said actors including state-sponsored APT groups kept exploiting unpatched VMware Horizon servers into 2022.

    Sources: [7] [5]

Impact

Log4j is built into thousands of software packages, so the flaw touched almost every networked organization, and many could not tell where they used it. Apache rated it 10.0, the maximum severity. Response was costly: one U.S. federal cabinet department spent 33,000 hours on it. Yet the CSRB found exploitation lower than experts feared and knew of no significant Log4j attack on critical infrastructure at the time. It calls Log4j an endemic vulnerability that may stay in systems for a decade or longer.

Sources: [6] [1]
