GitHub MCP server prompt-injection data leak (2025)

Invariant Labs showed that a malicious issue in a public GitHub repository could hijack an AI agent connected to the official GitHub MCP server. When the owner asked the agent to review open issues, it followed the issue's instructions, read data from the owner's private repositories and posted it in a public pull request. The researchers called it an agent design problem, not a server code bug. GitHub later added a lockdown mode that hides public content from users without push access.

Attack flow

or use ← →

  1. 1 Attacker opens a malicious issue in a public repository

    Initial Access Reported

    Attacker → Developer's public repository

    Anyone with a GitHub account can open an issue in a public repository. In the demonstration, the attacker opened an issue in the developer's public repository whose text was written to be read and obeyed by an AI agent rather than by a person. The attacker needed no access to the developer's account, the agent or the MCP server.

    Sources: [1] [4]

  2. 2 Developer asks the agent to review open issues

    Execution Reported

    Developer using an AI agent → AI agent (Claude Desktop)

    The developer used Claude Desktop with Claude 4 Opus and the official GitHub MCP server, and asked the agent a routine question about the open issues in the public repository. The agent's GitHub access also covered the developer's private repositories.

    Sources: [1] [4]

  3. 3 Agent reads the issue and adopts its instructions

    Execution Reported

    GitHub MCP server → AI agent (Claude Desktop)

    The agent fetched the open issues through the MCP server, so the attacker's text entered the model's context. The model treated that text as instructions to follow, which is an indirect prompt injection. The researchers note that even a well-aligned model was steered this way, so model training alone did not stop it.

    Sources: [1] [4]

  4. 4 Agent pulls data from private repositories

    Collection Reported

    AI agent (Claude Desktop) → Developer's private repositories

    Acting on the injected text, the agent used the MCP server's repository tools to read content from the developer's private repositories into its context. Claude Desktop asks users to confirm tool calls by default, but the researchers note many users choose to always allow them, so such calls can pass without close review.

    Sources: [1] [4]

  5. 5 Agent leaks the data in a public pull request

    Exfiltration T1567.001 Reported

    AI agent (Claude Desktop) → Developer's public repository

    The agent then opened a pull request in the public repository that contained the private data it had gathered. Because the repository is public, the attacker and anyone else could read the leaked details there. No server bug was used: every action went through normal MCP tools with the developer's own access.

    Sources: [1] [5] [4]

Impact

In the demonstration, details from the developer's private repositories, including a private project name, relocation plans and salary information, were published in a public pull request that anyone could read. The cited sources describe a researcher demonstration, not an attack on real users. Any agent that combines private data access, untrusted input and a way to publish data is open to the same pattern.

Sources: [1] [5] [4]
